# Briefing do produto

Preencha ao criar um repositório a partir do template. Campos sem resposta permanecem **a definir**; o agente não deve inventar aprovações ou responsáveis.

| Campo | Definição |
| --- | --- |
| Nome do produto e área | A definir |
| Responsável de negócio | A definir |
| Problema e impacto observado | A definir; referenciar evidência autorizada |
| Público e fluxo principal | A definir |
| Menor entrega útil | A definir |
| Critérios de aceite observáveis | A definir |
| Fora do escopo | A definir |
| Dados e fontes | Dados sintéticos no início; fontes reais a validar |
| Classificação e autorização dos dados | A definir com responsável |
| Identidade e permissões | A validar antes de expor informações internas |
| Uso de IA, modelo e limite de custo | A definir se necessário |
| Neon | Contratação, plano e acessos pendentes |
| Railway | Contratação, plano e acessos pendentes |
| Validações humanas necessárias | A definir conforme impacto |

## Critérios de aceite

Descreva cada critério como comportamento verificável: dada uma situação, quando a pessoa executa uma ação, qual resultado deve observar. Inclua casos vazios, dados inválidos e falta de permissão quando relevantes.

## Premissas e dúvidas

Registre a premissa, sua origem, o impacto e quem deve validá-la. Não apresente uma premissa do agente como decisão da Capricórnio.
